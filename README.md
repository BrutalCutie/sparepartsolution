# Проект SparePartSolution
### Какие цели преследует проект.
- Упрощения нахождения связи между тем кто ищет запчасти на свой автомобиль и продавцами/свалками/разборами которые обладают необходимыми запчастями.
- Увеличить кол-во продаж
- Более зелёный вариант: более грамотное расходование ресурсов земли. Запчасть, которая была выпущена, но имеет не до конца израсходованный ресурс будет использован до конца.

### Что ожидается в следующих версиях
- Улучшения по интеграции сервиса в свои программы путём получения и отправлениями данных по API:
    - Путём получения ключа авторизации:
      - Отклики на заявки
      - Отправка сообщений в чаты


- Отзывы и рейтинг продавцов
- Ответственность за передачу средств на платформу для безопасных сделок
- Ответственность за логистику, если продавец находится в другом городе
- Монетизация на подписках для ипользования сервиса для продавцов
- Более отзывчивый и удобный сайт с точки зрения UX

# Пример работы сервиса
## По хронологии:

### Регистрацию проходят
1. Иванов Иван - обычный пользователь, который ищет запчасти на свой а/м из Москвы.
2. Петров Пётр - Владелец московской свалки, который помимо регистрации добавляет свой магазин на сайте.
3. Иван создаёт заявку, что ему требуется новый бампер на его Kia Ceed.
4. Пётру приходит уведомление по почте (при регистрации можно выбрать метод получения уведомлений [Почта, Telegram]). Продавцы так же могут настроить для себя фильтры, согласно которым, они будут получать сообщения(напр. по слову Kia. Уведомления присылаются только если есть совпадение по городу/названии марки/названии модели/или словам в описании заявки)
5. Пётр откликается на заявку и пишет Ивану, что у него есть запчасть в наличии. Создаётся чат между Иваном и Петром.
6. Иван считает поступившее предложение очень выгодным и договаривается с Петром о доставке. Либо едет сам, это уже как они сами договорятся(взрослые же люди в конце концов)

## Итоги:
### Иван
#### Выгода: Просто, выгодно, быстро нашел то, что искал.
- Быстро получил ответ и не пришлось самому объезжать и обзванивать десятки продавцов с других площадок.
### Пётр
#### Выгода: Заработок и довольный клиент.
- Продал запчасть, которая была в наличии.


## Мораль:
Вот так просто, сервис, образовал связь между продавцом и покупателем и в результате все остались в выигрыше.
<br>
Таких Иванов и Петров может быть десятки или сотни, что сильно упростит жизнь всем.

# Функциональная часть
- ## Интерфейс сервиса
  - Регистрация
  - Верификация почты
  - Аутентификация
  - Создание заявки
  - Настройка получения уведомлений
  - Создание магазина
  - Возможность откликнуться на заявку(если вы продавец и у вас есть магазин)
  - Настройка фильтров для получения уведомлений по новым заявкам

- ### Немного об основных зависимостях проекта
  - django
      - отличный сервис для создания Web приложений.
      - легкий в обращении.
      - отличная ORM.
  - django restframework
      - позволяет просто управлять запросами API.
      - очень подробная документация.
  - celery
      - одно из основных приложений для уравления отложенными задачами.
      - простая настройка
  - redis
      - тоже одна из базовых вещей.
      - отличный брокер для управления кэшем и не только


- ### Необходимые данные для запуска
  - SECRET_KEY - ваш секретный ключ django
  - База данных:
    - POSGRES_DB - название вашей
    - POSTGRES_USER - имя пользователя
    - POSTGRES_PASSWORD - пароль пользователя
    - POSTGRES_HOST - название сервиса docker контейнера отвечающего за Postgresql
    - POSTGRES_PORT - порт
  - Настройки SMTP:
    - EMAIL_HOST - сервис. Напр. smtp.yandex.ru
    - EMAIL_PORT - порт
    - EMAIL_USE_TLS - используемый протокол (True | False)
    - EMAIL_USE_SSL - используемый протокол (True | False)
    - EMAIL_HOST_USER - пользователь, от чьего лица будут исходить сообщения почты 
    - EMAIL_HOST_PASSWORD - пароль
    - DEFAULT_FROM_EMAIL - обычно тот же что и EMAIL_HOST_USER
  - Брокер
    - BROKER_URL - расположение сервера
    - RESULT_BACKEND - обычно то же что и BROKER_URL
